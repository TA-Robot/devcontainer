# 協働の実測と適用範囲

更新: 2026-09-06。方式の選択時に[協働モデル](collaboration-model.md)と一緒に参照する。
使い方の説明、実行できた証拠、成果への効果を区別し、未測定を改善率で埋めない。

## 事前相談による証拠統合

対象はF12-L revision 3の、公開された数値・根拠ID・移行制約を最終記録へ統合する限定課題。
gpt-6-astra/highを要求したCodex実行で、soloと「事故・隔離・移行を先に点検するadvisor→fresh maker」を一組比較した。
[protocol・結果・出典](../../experiments/development-harness/consultation/synthesis-result.md)。

| 観測 | 現在の判断 |
| --- | --- |
| 元の固定得点は両方10/12だが、否定表現と関連unknownの重複に対する誤判定を校正で再現 | 品質改善の判断は保留。得点を上書きせず、品質付き速度比を出さない |
| 相談側の提出までの時間19.3%増、input44.8%増、output6.5%増 | この条件で常時事前相談を既定化する根拠はない |
| 独立した助言の受渡しと全参加者の停止・消費回収は成立 | 運用経路の証拠。助言の有用性や他の協働方式の効果とは分ける |

AIがこの観測を使う際は、課題、公開tool、model要求、直列の関係、全体予算、評価の限界を添える。
他の課題、途中の相談、独立review、複数案・複数実装、並列分業へ数値を移し替えない。
同じ公開検査で自己検証できる場合に、事前相談を自動追加する一般規則は作らない。
相談するなら、追加の観点・証拠がどの判断を変えるかを具体化し、全費用を見て採否を決める。

次の仮説は、公開情報を一通り点検した後の具体的な不足に対する相談が、常時事前相談より
無駄を減らせるか。まだ比較していないので推奨や改善率は付けない。
現在のdatumはduration atlasへ混ぜず、独立したpilot記録として保持する。

## 評価器に戻す学習

known-goodと悪い成果を区別できるだけでは、協働比較の準備完了ではない。
正しい否定表現、関連する複数の根拠、妥当な別表現も受理できる必要がある。
この校正が失敗したら、改善率の集計を止めて版を分けて修理する。人やLLMの採点で埋め合わせない。
新しい評価版と確認課題での再比較が終わるまで、一般的な品質改善を主張しない。

[synthesis scope v2](../../experiments/development-harness/consultation/synthesis_v2/README.md)で、
scopeとtopicを公開された構造で判定する評価を実装・校正した。正当な10候補の受理と、
構造化された過剰一般化・根拠欠落など27候補の拒否を確認したが、自由文の虚偽と無効な
運用手順の2候補は通る。この限界を含めて校正結果とし、旧pilotの品質保留は解除しない。
AIへ返す学習は「検査できる性質を明示し、未測定の品質を得点から推測しない」。
この評価器の修理は、相談そのものによる品質・速度の改善を示す実測ではない。
