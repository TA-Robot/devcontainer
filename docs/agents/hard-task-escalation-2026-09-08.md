# 難度を大きく広げる: scheduling次版の設計方針

2026-09-08、ユーザーの「もっと大きく難しくすべき」という指摘を受けた方針修正。
旧H2の2回の成功・得点・protocolは保存する。本書は新課題の設計方針であり、live開始許可枠ではない。
その後、[公開契約・動的実行器・96実行の初回校正](../../experiments/development-harness/scheduling/dynamic_v1/result.md)を実装した。
強い参照・到達水準・strong soloの難度校正は引き続き次の作業である。

## 足りなかったもの

旧版は全job・依存・所要時間が既知、32〜72job、4/8worker、一つの参照heuristicのvectorが到達目標だった。
強い単独は複数案・探索・自作検証を使い、2回とも全目標へ到達した。
評価の隔離と採点は成立したが、目的に必要な高い成果水準と探索の広さを十分に設計できていなかった。
参照実装が動くことと、十分高い目標を用意したことを混同していた。

容易だった版から別分野の最小課題へ移ることを、標準の次手にはしない。
同じ題材で必要な成果と相互作用を大きく広げ、難度の広い範囲を先に用意する。
単独の予算・toolを削る、未知の必須仕様を隠す、締切を実現不能にする方法は使わない。

## 欲しい成果と課題の拡張

継続的に到着する依存jobを、異なる資源・締切・障害の下で処理する実行計画policyを開発する。
一度の静的な割当の改善から、状況が変化しても有用な仕事を期限内に完了できる制御へ広げる。
UIやscheduler製品全体の開発は要求せず、実行できるpolicyとその実験・選択・修正を成果物にする。

| 相互作用 | 実装に求める判断 | 測る成果 |
| --- | --- | --- |
| 継続到着、異なる締切・優先度、依存関係 | 今すぐ処理する仕事と、後の重要な仕事のために残す資源 | 優先度別の期限内完了、待ち時間の裾、未完了仕事 |
| 専用資源、共有メモリ等の容量、cache切替え | 並列度・配置・まとめ処理を同時に決める | 制約違反なしでの有用な完了量と資源消費 |
| worker停止・復帰、実行時間の変動 | 失敗検出後の再計画と、過去の観測を使う推定 | 障害区間のサービス低下と復帰、再実行費用 |
| 平常・突発負荷・希少資源・cache競合の混在 | 一つの規則への固定、切替え、組合せを実測で選ぶ | 系列別の品質と最悪領域。平均による失敗の隠蔽を防ぐ |

これらは新規実装が必要な能力。旧v1には到着event、任意時刻の待機、障害回復等がない。
観測できるもの・できないもの、再試行の意味、資源の保持/解放を公開契約で先に定義する。
未来を知らなければ不可能な判断を正解として要求しない。

## 難度を広く測る方法

一つの弱い参照を越えるだけの合否から、合法性、成果の品質、資源、未達の位置を持つ評価へ変える。
正常負荷、強い競合、障害を含む混合負荷を最初から同じ課題族に置く。
規模だけでなく負荷率・競合・変動の範囲を大きく離し、易しい条件から順番にliveを繰り返さない。
具体的な帯域・ケース数は非agent校正の費用と識別力から固定する。ここでは未測定の数値目標を置かない。

参照は優先度規則だけでなく、割当最適化、先読み、状態に応じた切替え等の有効な方式を含める。
同じ公開情報・実行資源で動く参照成果を到達可能性の根拠にする。
将来情報を使うoffline解・理論限界は品質の余地を測る補助であり、online側の必達目標にはしない。
複数方式の指標ごとの最小値を継ぎ合わせ、存在しない理想解を要求しない。

到達水準は、期限内に処理すべき仕事や許容するサービス低下から理由を示して固定する。
到達可能な強い解があり、弱い規則との差があり、方式間の優劣が状況で変わる範囲を選ぶ。
合法に動くだけで高得点になる範囲と、誰にも達成根拠のない範囲を区別する。
固定した開発・校正の難度帯をまとめてstrong soloで調べ、成功帯も失敗帯も全て残す。
旧confirmationを新しい探索用データに使わない。

## 比較へ進む判断

完全な単独不可能性の証明や、安定した失敗率の精密推定を、最初の協働探索の前提にしない。
妥当な評価と強い到達可能水準があり、十分に試行したsoloに意味ある未達が残り、
探索・選択・統合など協働で変え得る障害の仮説があれば、有限な協働探索へ進む。
その後に固定する確認比較と探索を区別し、協働が勝った条件だけで一般効果を主張しない。
全帯域で容易だった場合は題材を自動変更せず、上限の低さ・要求の弱さ・方式の飽和を判断する。

## 次に作る具体物

次の成果物は、この課題の公開動作契約、広く離れた負荷帯の生成仕様、品質vector、参照方式の校正設計。
到着・障害・資源を評価側が所有する最小event実行器へ接続し、provider-freeで成立と識別力を確かめる。
汎用ハーネスや別分野のadapterを先に増やさない。liveの全予算と停止はその校正費用から別途固定する。
ownerはprimary/integrator。この優先順位は今回のユーザー訂正に基づくplanning priorであり、
公開情報だけでは成果水準が不可能、非agent参照にも識別力がない、実装範囲が研究対象を逸脱する場合に見直す。
