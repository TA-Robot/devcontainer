完了条件は、旧記録を保持した診断、実行前の拒否、実processの中断復旧、

この観測系列は、数十分の比較を週単位の結果に言い換えるものではない。
今後の実要求による変更、変更後の退行、旧状態の読み取り、利用時の復旧、
引き継ぎと配布までを同じ実装の履歴として蓄積する。独立な小問の件数や
経過日数だけを「大規模の評価が完了した」条件にしない。

| 観測 | 保存する根拠 | 判定の限界 |
| --- | --- | --- |
| 実際の要求と変更 | 着手時点のscope、開始revision、成果commit、採否 | 後から追加した要求を元の不合格に数えない |
| 動作と品質 | 公開された利用手順、実行結果、追加レビュー、旧状態の維持 | 通過件数を総合品質点にしない |
| 変更の継続 | 先に通った利用経路の退行と修復、手順の変更 | ステージを独立sampleとして増やさない |
| 時間・費用 | 実行が記録した開始／終了、usage、外部検証を別記 | commit日時は作業時間ではない。未計測のprimary開発・人間review時間はunknown |
| 実利用 | 導入・利用・復旧の実記録と失敗 | 校正用fixtureを実ユーザー利用の成功に換算しない |

最初の記録では、旧A/Bの予算診断は過去の記録を読む観測、疑似providerは開始制御の
校正、同梱checkerは配布版の復旧手順の確認として分ける。
速度効果、金額、人間の負担、週単位の保守性は現時点でunknown。

次の実要求が発生したとき、primaryがそのscopeと比較・観測方法をこの系列へ追加する。
ユーザーへlog保守や定期報告を求めない。起動しっぱなしのagentやschedulerは作らず、
各開発・検証を有限jobとして終了する。paired比較を再開する場合は別の新課題として
条件・順序・品質基準・予算の最低値を先に固定し、この観測系列と区別する。
