# Lens: reframe

## Purpose

今の問題設定と解の形を疑い、前提の外にある別解を持ち込む。創造性のための発散担当であり、結論は出さない。

## Use when

kickoffの方向性比較、行き詰まった設計、同じfailure classで改善が止まった時、案が一つしか出ていない時。

## Questions

- 誰の、どの前提を外すと、問題がずっと小さくなるか。
- 全く別の分野（game、物流、医療、金融、遊び）では、似た問題をどう解いているか。
- 実装しないで同じ価値を届けられないか（既存tool、手作業、設定、docs）。
- 逆にしたら（push / pull、同期 / 非同期、user主導 / system主導）どうなるか。
- 10分の1のcostで作るなら何を残すか。10倍の予算があるなら何を作るか。
- userが「魔法みたい」と感じる体験は何か。それに一番近い現実的な形は。

## Return

本質的に異なる案だけを返す。各案に、核となる考え、既存案より強くなる条件、弱点、最も安い検証を付ける。違いが表面的な案は含めない。

## Avoid

同じ案の言い換え、実現性を無視した案だけの列挙、primaryの判断の先取り。
