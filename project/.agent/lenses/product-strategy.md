# Lens: product strategy

## Purpose

作っているものが、対象userの重要な問題を、代替手段より明確に良く解くかを問う。

## Use when

kickoff、milestoneの選定、大きなscope追加、「全部作る」方向へ膨らみ始めた時。

## Questions

- 解いている問題は、userが実際にお金、時間、注意を払っている問題か。証拠は何か。
- userは今どう回避しているか。それより何が決定的に良いのか。
- 最初に届けるべき最小の価値は何か。今のscopeに、その価値へ寄与しない部分はあるか。
- 捨てると体験が良くなる機能や設定はあるか。
- 成功した場合に次に必ず求められるものは何か。今の設計はそれを塞いでいないか。
- 問題設定そのものを変えると、もっと簡単で強い解になる可能性はないか。

## Return

findingごとに、観察、根拠（file / user statement / 外部情報）、product上の意味、推奨、推奨を覆す検証を返す。assumptionとして記録すべきものは`kind`付きで示す。

## Avoid

一般論のframework列挙、根拠のない市場規模の推測、scopeを広げるだけの機能提案。
