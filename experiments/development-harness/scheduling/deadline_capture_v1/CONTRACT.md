# Prospective termination-capture contract: synthetic calibration only

2026-09-09; owner primary/integrator. This contract is a new measurement candidate.
It cannot reopen, reclassify or assess the withheld continuation pair. This module
has no live entry point or credential argument and uses only a synthetic provider.

The measurement is the designated artifact after observed termination and recovery.
Normal completion and a requested development-deadline stop remain different
lifecycle outcomes. A deadline never becomes normal completion. The original
actor report, wall-clock exceeded flag, usage gaps and output admission remain
unchanged. A new sidecar states whether these captured bytes can be evaluated.

An artifact is eligible only after container/credential removal, source-integrity
checks and sealing of the designated `submission.py`. There is no retrospective
choice of another candidate. Unknown cleanup, missing artifact, unsupported model
binding, an unexpected execution/collection failure or unknown capture timing
withholds evaluation. A malformed submission may be captured and then classified
as invalid policy by the independent evaluator; capture is not quality success.

For a deadline stop, the native bridge must explicitly report its development
deadline, and participant failures may contain only unfinished/aborted-turn
markers. Other tree, metadata and inventory failures are not relaxed. Every
participant must still be bound to gpt-6-astra/high and CLI 0.153.0. A solo must
still have one participant. The native process/container stops before sealing,
so an active child cannot continue editing after capture.

There is a real delay between requested cutoff, termination and source capture.
The bridge duration and the actor's elapsed time (which also includes preparation
and recovery) are both retained. The latter is a conservative upper bound on the
artifact capture window, not CPU time or exact time of the last edit. In this
calibration, a **20-second recovery bound** above the requested window is a hard
guard, covering existing container startup/stop and observation overhead. It is
not a granted 20 seconds of additional development or a silent rounding of the
old 40-minute limit. Overshoot beyond it or unknown timing withholds capture.
This guard is scoped to the fixed image/CLI and must be reconsidered before live
if calibration cannot bound recovery. The owner is primary/integrator.

Synthetic normal execution has a 30-second window; deadline probes use 8 seconds.
These are finite test cost caps, not proposed live developer budgets. Probe
assessment has a 120-second cap and uses only the existing public probe. No old
qualification input or live artifact is assessed. Normal, valid deadline,
invalid deadline, missing submission, active child and external interruption
must be distinguished. Source/capture/manifest tampering must block grading.
The child probe continues writing harmless comments until it is stopped; the
captured source must remain unchanged throughout independent grading. The frozen
evaluator exits zero even when its case report says invalid-policy. The new
adapter therefore checks raw case statuses as well as exit, coverage and cleanup;
nonzero exits or unmeasured cases remain withheld. Older adapters and scores are
not changed to this classification.

For a future live comparison, the requested window, measured recovery bound,
cutoff behavior, common task, starts/order, output caps and missing-data treatment
must be prospectively fixed in a new protocol. Quality would be reported at
observed termination with its timing bound, not as certified exact-cutoff quality.
No such live comparison is implemented or authorized by this calibration file.
