# Prospective continuation pair

Fixed before model starts, 2026-09-09. Owner: primary/integrator.
This is a new capability exploration from a common strong starting artifact.
It neither reopens the refinement cohort nor certifies its rejected instruction.

## Question and conditions

Can adaptive collaboration improve an existing strong implementation beyond a
strong solo developer given the same initial source and additional development
budget? Both may modify, replace or retain the initial implementation. Solo keeps
self-review, alternative implementations, case generation and code execution.
Adaptive uses the standard native collaboration instruction, not the unpromoted
failure-refinement instruction. The expected mechanisms remain independent
exploration and evidence-producing refinement/integration of remaining weaknesses.
No number of participants, conversations or edits is a required outcome.

The fixed initial source is the previously selected solo artifact with SHA256
`24c82c7e2fbc98edb73a384170074da8bf0240eb5203179aa253cbe9a5055424`.
It is a common starting point, not a stationary solo control. Both developers
start fresh sessions with the same public bytes, without previous conversations,
private assessment inputs or scores. Both are free to replace this source.

Serial order: **solo, adaptive**, one start each, no retry or replacement. Both
use gpt-6-astra/high, pinned CLI 0.153.0, the same actor image, 1 CPU / 2 GiB,
90s per scenario / 5s per policy response. Adaptive has native four-slot capacity
including the root, not a recommended team size. All participants share its CPU,
memory and development clock. The information difference is native collaboration
capability and its standard role instruction. The continuation note is identical.

## Inputs and separation

Use the unchanged dynamic workload generator, public seed base 15485863 and
assessment seed base 32452843, expanding by family*1000 + band*100 + replicate.
Each population has three bands, four families, two replicates: 24 scenarios.
Seeds are selected without observing candidate scores. These are fresh instances
of an already explored family, not new task families or untouched confirmation.
No previous confirmation is consumed.

The common public bundle adds only `initial.py` and `INITIAL.md` to the existing
nine-file projection. The authoring generator, seeds, private input, provenance
record and other developers' work are not mounted into actors. Initial-source
provenance is retained outside the public bundle. The baseline is code data on
the host and executes only in the isolated actor or evaluation containers.

Before any qualification scoring, both normal selected artifacts, actor results,
public bytes and initial source must be sealed. Recheck the barrier before each
assessment. Grade the unchanged initial source, then solo and adaptive, on the
same sealed 24 qualification inputs with the unchanged independent evaluator.
The initial source is a fixed non-agent baseline, not a model start or advisor.
No assessment feedback returns to either developer. Never subtract scores from
different old populations to calculate improvement.

All limits are owned by primary/integrator and fixed by config for this campaign.
Unknown usage and observed output excess do not erase normally completed artifact
quality. Continue the registered pair, retain output-budget admission as withhold,
and distinguish unknown from exceeded. Deadline, abnormal participant termination,
missing submission, unknown cleanup or a changed source stops subsequent starts
and scoring. Record attempted starts exclusively before calling the actor. No
failure opens another start or a continuation of a previous session.

Live requires source-matched native validation, this pair's normal / usage-gap /
output-excess / deadline / outer-interrupt checks, baseline and public-bundle
tamper rejection, and public FIFO/initial calibration on all 24 inputs. Compare
public execution with independent Docker results, including traces. Qualification
is validated and sealed at calibration, never scored to select these inputs.

## Reporting and decision

Primary: adaptive minus newly developed solo. Also report each final artifact
minus the unchanged initial source on these same inputs. Preserve all cases,
cells and bands, on-time value, critical service/denominators, unfinished value,
censored deficit, completed-only response tails/sample sizes and worker use.

An aggregate Pareto increase in value/critical service is a promising observation
only if every band's critical service is nondecreasing. Require adaptive to meet
this criterion against **both** the newly developed solo and the initial source
before classifying this exploratory pair as promising. Otherwise preserve all
tradeoffs; do not revise the rule after scores. This is a scoped hypothesis/triage
criterion, not proof of stable capability extension or of single-agent impossibility.

The initial source's prior construction cost is a shared sunk cost, excluded from
additional-development usage but explicitly retained in provenance. Total project
cost, outer preparation/review and invoice completeness are unmeasured. Equal
ceilings and time do not imply equal realized tokens, compute or money. Unknown
usage prevents certified token-budget and cost-efficiency claims. Starting-source
anchoring, fixed order, model variation and one run per condition limit attribution.
Unproductive dialogue or unchanged source is not automatically failure: evaluate
the selected artifact, not activity volume. No extra judging model calls occur.
