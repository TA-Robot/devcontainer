## この診断が言えること・残る不明

これは developer が保存した公開実験記録の再集計であり、独立 Docker 採点ではない。
case ID、公開の母数、class 別件数と価値の整合、利用可能な source/input hash を確認した。
input/source が一致しても、実行内容の独立認証や記録の真実性の証明にはならない。
fast runtime の記録も区別して保持する。既存の最終成果の外部診断とは測定範囲を混ぜない。

公開24例の完全な記録がない候補は上限に含まれない。未保存候補や未測定の設定まで不可能としない。
候補の内部を組み合わせる新しい実装や、候補を改良する行為もこの上限の外にある。
この結果は「選択支援だけを先に作る」という仮説を弱めるが、失敗原因を一意に確定しない。

より高い成果を出す候補が単独側に存在したことは、協働側の改善余地の手掛かりになる。
強い単独自体の未達がどこまで改善可能か、方式が安定して能力を拡張するかは未確定。
100% 配送との差を、達成可能な未達量と数えない。
