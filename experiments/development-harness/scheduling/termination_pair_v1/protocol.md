# Prospective termination-capture continuation pair

This is a new finite experiment, `scheduling-termination-pair-20260910-01`.
It does not reopen the deadline-withheld continuation pair or its unused slot.
Its target is better discovery, testing, selection and integration from an already
strong implementation. The main contrast is adaptive collaboration versus a
fresh strong solo developer with the same initial source and additional budget.

The shared initial artifact is `continuation_pair_v1/initial-policy.txt`, SHA-256
`24c82c7e2fbc98edb73a384170074da8bf0240eb5203179aa253cbe9a5055424`.
Its provenance and shared sunk construction cost remain in that version's
`protocol.md` and the refinement cohort's result records. No old scores or developer reports enter actors.
The deadline-withheld later artifact is not selected as the new initial source.

## Mechanism and conditions

The adaptive instruction is the frozen `adaptive_pair_v1/adaptive.md`: independent
perspectives and tests can expose blind spots, alternative implementations can
improve the candidate pool, and the root can select and integrate evidence.
Native collaboration is available, with no required team size or exchange count.
Solo retains code execution, self-review, alternative designs, sequential trials
and local experiments. Neither condition receives qualification feedback.

Both use the unchanged native recovery actor, pinned gpt-6-astra/high and CLI
0.153.0, one CPU and 2 GiB per actor. The public projection is the same eleven
files including the initial source and new common `INITIAL.md`. Only native
collaboration availability and its instruction differ. Developer code remains
isolated from provider credentials, observation records and private assessment
inputs. Candidate code never executes on the host.

Public seed base 49979687 and assessment seed base 67867967 are fixed before
assessment. Each produces 24 cases covering the existing workload cells. These are new instances
of an explored family, not new task-family discovery or confirmation. Calibration
validates and seals qualification inputs without scoring them or selecting seeds
by quality. Public FIFO and initial results must match independent Docker results
on all 24 public inputs, including complete result records and traces.

## Capture and finite bounds

This protocol measures the designated artifact **after observed termination and
recovery**. It does not measure exact requested-cutoff quality or certify normal
turn completion. Each start ledger fixes the requested window and recovery bound
before launching its actor. Source, prompt, common input and initial bytes are
sealed prospectively. The native actor removes its container and credential copy
before freezing the regular `/work/submission.py` file. No post-stop candidate
selection, revision or fallback to another work file is permitted.

The separately validated `deadline_capture_v1.capture.classify` is applied to
new records only. Normal completion and the exact native development-deadline
stop may be captured. The original quality, lifecycle, wall-clock budget, usage
and admission records remain unchanged. Unexpected interruption, missing artifact,
unknown cleanup, source/model/participant mismatch, unknown timing or excessive
capture window stops subsequent starts and assessment. Active children are stopped
with the actor container before capture. A file interrupted during editing is
assessed as those actual frozen bytes, not repaired by the harness.

| 900 seconds per assessment, three artifacts | cost cap | Unchanged initial and both captured artifacts; no extensions |

| Same starting source, public bytes, sandbox and seals | hard guard | Required attribution and isolation boundaries |

The integrator owns these limits for this campaign; failure, evidence of insufficient
recovery or invalid measurement can motivate a future protocol, never alter this
one after starts. Report requested time, observed bridge development time and the
conservative capture upper bound (native elapsed time includes setup and accounting).
Do not label these CPU time or assume equal realized work from equal allowances.

Preflight found late-created containers after a client-side Docker create timeout:
an immediate absence check had incorrectly claimed recovery. The new outer audit
therefore requires evidence the container ran before confirming absent resources.
When create completion is uncertain, observe for the fixed window and remove any
owned container that appears, but retain recovery as unknown even after removal:
seeing one object does not prove the pending daemon operation has finished. Old
cleanup records remain unchanged; the new audit and its uncertainty are separate.

Capture eligibility is independent of usage completeness. Missing usage or observed
output excess retains artifact quality but withholds output-budget admission. Keep
unknown and exceeded distinct. Known usage is a lower bound when records are missing;
root stdout does not certify all-participant usage or invoices. Original episode
admission remains a separate field, including deadline lifecycle withholds.

## Barrier, assessment and interpretation

Both new captures must be sealed before any assessment, including the initial
baseline. Recheck source, actual prompts, captures, original actor reports, initial
bytes, public bundle and private inputs before and after assessment. Grade initial,
solo and adaptive on the same sealed inputs with the unchanged timing evaluator
and the validated deadline-capture assessment adapter. No new model judge is used.

Measured and confirmed invalid-policy cases are distinct from unmeasured evaluator
failures. An invalid artifact remains an invalid outcome; retain the other registered
assessments but do not fabricate numeric scores or a successful quality comparison.
Unexpected evaluation failure withholds the comparison. Execution completion does
not mean successful policy, admitted budget or proven collaboration improvement.

For fully measured artifacts, preserve all cases, cells and bands: on-time value,
critical service and denominators, unfinished value, censored deficit, completed-only
response tails and sample sizes, and worker use. Primary comparison is adaptive
minus fresh solo; also compare each against the unchanged initial source on these
same inputs. Frozen triage requires aggregate value and critical service nondecreasing,
one strictly increasing, and critical service nondecreasing in every load band.
Adaptive must satisfy this against both solo and initial to be promising. This is a
scoped hypothesis, not stable effect, single-agent impossibility or cost efficiency.

Live starts require source-matched native and capture validations, the complete
new-pair synthetic preflight, and matching full public calibration. The exclusive
campaign path and per-start ledgers allow at most one attempt per condition.
Failure closes unused starts; no resume, replacement candidate or retry is granted.

Synthetic deadline fixtures use a 20-second window (planning prior for reaching
the intended failure point) and a 30-second first-tool wait. The original 8-second
prototype sometimes stopped during CLI/tool startup before submitting any file.
This fixture adjustment does not change the live 2400-second window, its capture
bound or any old result. The integrator owns the fixture prior; failure to reach
the designated point invalidates that calibration, not the production guard.
